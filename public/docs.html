Tài liệu API Thu chi · v1

Đọc giao dịch ngân hàng, số dư, báo cáo thu chi và tạo yêu cầu thu tiền bằng VietQR. Dữ liệu được đồng bộ tự động từ SePay.

Tổng quan

Base URL:

https://YOUR-DOMAIN/api/v1

Mọi request và response dùng JSON, mã hoá UTF-8. Số tiền là số nguyên, đơn vị VNĐ. Thời gian theo giờ Việt Nam (UTC+7), định dạng YYYY-MM-DD HH:mm:ss, riêng created_at và paid_at theo UTC.

Quản trị viên cấp API key ở mục API & tích hợp trong hệ thống. Mỗi key có thể chỉ có quyền đọc, hoặc thêm quyền tạo yêu cầu thu tiền, và có thể bị giới hạn chỉ thấy một số tài khoản ngân hàng.

Xác thực

Gửi API key trong header Authorization ở mọi request:

Authorization: Bearer tc_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Hoặc header X-API-Key: tc_.... API key có toàn quyền trong phạm vi được cấp, chỉ dùng ở server, không đặt trong mã chạy trên trình duyệt hay ứng dụng di động.

Định dạng phản hồi

{
  "status": "success",
  "data": [ ... ],
  "meta": { "pagination": { "total": 150, "per_page": 50, "current_page": 1, "last_page": 3, "has_more": true } }
}

Chi tiết giao dịch

GET/api/v1/transactions/{id}

Lấy giao dịch mới (polling)

Lưu id lớn nhất đã xử lý, mỗi lần gọi truyền since_id bằng giá trị đó. Kết quả sắp xếp theo id tăng dần; đọc hết các trang (has_more) rồi mới cập nhật since_id. Nên gọi 1 đến 5 phút một lần.

GET /api/v1/transactions?since_id=1250&per_page=100

Tài khoản ngân hàng

GET/api/v1/accounts

Trả về các tài khoản key được phép xem: account_number, bank, holder, label, balance, last_transaction.

Danh mục

GET/api/v1/categories

Danh sách id, name, type (in / out), dùng để hiểu category_id hoặc gắn danh mục khi tạo yêu cầu thu.

Tạo yêu cầu thu tiền

POST/api/v1/payment-requests

Cần API key có quyền tạo yêu cầu thu tiền. Hệ thống sinh mã thanh toán duy nhất và link ảnh VietQR. Khi khách chuyển khoản có mã này trong nội dung và đủ số tiền, yêu cầu tự chuyển sang paid.

Trường bodyKiểuMô tả
amountinteger, bắt buộcSố tiền cần thu
customerstringTên khách hàng
descriptionstringMô tả nội bộ, vd mã đơn hàng của bạn
category_idintegerDanh mục thu gắn cho giao dịch khi tiền về
codestringTự đặt mã thanh toán (chữ và số). Bỏ trống để hệ thống sinh
account_number, bankstringTài khoản nhận tiền. Bỏ trống để dùng tài khoản mặc định

Trạng thái yêu cầu thu

GET/api/v1/payment-requests/{code}

status: pending (chờ thu), paid (đã thu đủ), cancelled (đã huỷ). paid_amount cộng dồn nếu khách chuyển nhiều lần.

Code mẫu

Node.js

const BASE = 'https://YOUR-DOMAIN/api/v1';
const headers = { Authorization: `Bearer ${process.env.THUCHI_API_KEY}` };

let sinceId = 0; // lưu lại trong database của bạn
async function pollNewTransactions() {
  for (let page = 1; ; page++) {
    const r = await fetch(`${BASE}/transactions?since_id=${sinceId}&per_page=100&page=${page}`, { headers });
    const { data, meta } = await r.json();
    for (const t of data) { /* xử lý giao dịch t */ }
    if (data.length) sinceId = Math.max(sinceId, ...data.map((t) => t.id));
    if (!meta.pagination.has_more) break;
  }
}

Giới hạn & lưu ý

  • Giao dịch ngân hàng về hệ thống qua webhook SePay trong vài giây; đối soát tự động chạy mỗi 5 phút để bù giao dịch bị sót.
  • Nên gọi API không quá 5 request mỗi giây. Polling 1 đến 5 phút một lần là đủ.
  • Không có API sửa hoặc xoá giao dịch ngân hàng: dữ liệu ngân hàng là nguồn gốc để đối soát.
  • Nếu nghi lộ API key, báo quản trị viên thu hồi và cấp key mới.

Tài liệu này dành cho đối tác được cấp API key. Liên hệ quản trị viên hệ thống để được cấp quyền.
