Tổng quan

Base URL:

https://YOUR-DOMAIN/api/v1

Mọi request và response dùng JSON, mã hoá UTF-8. Số tiền là số nguyên, đơn vị VNĐ. Thời gian theo giờ Việt Nam (UTC+7), định dạng YYYY-MM-DD HH:mm:ss, riêng created_at và paid_at theo UTC.

Quản trị viên cấp API key ở mục API & tích hợp trong hệ thống. Mỗi key có thể chỉ có quyền đọc, hoặc thêm quyền tạo yêu cầu thu tiền, và có thể bị giới hạn chỉ thấy một số tài khoản ngân hàng.

Xác thực

Gửi API key trong header Authorization ở mọi request:

Authorization: Bearer tc_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Hoặc header X-API-Key: tc_.... API key có toàn quyền trong phạm vi được cấp, chỉ dùng ở server, không đặt trong mã chạy trên trình duyệt hay ứng dụng di động.

Kiểm tra kết nối

Gọi endpoint này đầu tiên để biết API key hợp lệ và key được cấp những quyền gì. Không tốn phí, không gọi sang SePay, Goship hay eSMS.

Vận chuyển Goship

Hệ thống kết nối với một hoặc nhiều tài khoản Goship. Qua các endpoint dưới đây, phần mềm của bạn tra cước của các hãng (GHN, GHTK, Viettel Post, J&T, Best, SPX…), tạo vận đơn, theo dõi trạng thái và huỷ đơn, mà không cần giữ Access Token Goship.

Cần API key có quyền Goship. Key có thể bị giới hạn chỉ dùng một số tài khoản Goship. Mỗi key chỉ xem và huỷ được vận đơn do chính key đó tạo.

Luồng chuẩn: lấy mã địa giới (tỉnh, quận, phường) → tra cước → chọn một rate → tạo vận đơn → theo dõi trạng thái bằng polling updated_since.

Mọi endpoint Goship nhận tham số tuỳ chọn account_id (query hoặc body) để chọn tài khoản Goship. Bỏ trống thì dùng tài khoản đầu tiên key được phép dùng.

Tài khoản Goship được dùng

GET/api/v1/goship/accounts
{ "status": "success", "data": [ { "id": 1, "name": "Shop FarmBase", "env": "production",

sender là địa chỉ lấy hàng mặc định của tài khoản, được dùng khi bạn không gửi address_from.

Mã địa giới là mã của Goship, dùng cho tra cước và tạo đơn. Dữ liệu ít thay đổi, nên lưu đệm ở phía bạn.

Xác minh số điện thoại (OTP)

Hệ thống sinh mã OTP, gửi tới số điện thoại qua eSMS bằng SMS brandname, Zalo ZNS, hoặc Zalo trước rồi tự chuyển SMS nếu Zalo lỗi, và kiểm tra mã người dùng nhập. Bạn không cần tài khoản eSMS và không phải tự lưu mã.

Cần API key có quyền Xác minh SĐT. Key có thể bị giới hạn chỉ dùng một số tài khoản eSMS. Mỗi key chỉ kiểm tra được mã do chính key đó gửi.

Luồng chuẩn: gửi mã → giữ request_id → người dùng nhập mã → kiểm tra mã với request_id đó. Chỉ coi số điện thoại là đã xác minh khi nhận "verified": true.

Giới hạnGiá trị
Gửi lại cho cùng một sốSau tối thiểu 60 giây
Số mã mỗi số điện thoạiTối đa 5 mã mỗi giờ
Nhập saiTối đa 5 lần mỗi mã, sau đó mã bị khoá (locked)
Hiệu lực mãTheo cấu hình tài khoản eSMS, mặc định 300 giây

Code mẫu

Node.js

const BASE = 'https://YOUR-DOMAIN/api/v1';
const headers = { Authorization: `Bearer ${process.env.THUCHI_API_KEY}` };

let sinceId = 0; // lưu lại trong database của bạn
async function pollNewTransactions() {
  for (let page = 1; ; page++) {
    const r = await fetch(`${BASE}/transactions?since_id=${sinceId}&per_page=100&page=${page}`, { headers });
    const { data, meta } = await r.json();
    for (const t of data) { /* xử lý giao dịch t */ }
    if (data.length) sinceId = Math.max(sinceId, ...data.map((t) => t.id));
    if (!meta.pagination.has_more) break;
  }
}

Giới hạn & lưu ý

  • Giao dịch ngân hàng về hệ thống qua webhook SePay trong vài giây; đối soát tự động chạy mỗi 5 phút để bù giao dịch bị sót.
  • Nên gọi API không quá 5 request mỗi giây. Polling 1 đến 5 phút một lần là đủ. Các API Goship còn chịu giới hạn chung 300 request/phút của mỗi tài khoản Goship.
  • Không có API sửa hoặc xoá giao dịch ngân hàng: dữ liệu ngân hàng là nguồn gốc để đối soát.
  • Nếu nghi lộ API key, báo quản trị viên thu hồi và cấp key mới.

Tài liệu này dành cho đối tác được cấp API key. Liên hệ quản trị viên hệ thống để được cấp quyền.
